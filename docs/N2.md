Avaliação N2
Este documento é apenas um detalhamento do que consta no "Escopo do Projeto" referente à N2, com
o objetivo de deixar explícito o que e como deve ser entregue e como cada item será avaliado.
1. Escopo
   Para a N2, o foco é substituir os dados mock utilizados na N1 por uma integração real com banco de
   dados (Firebase Firestore). As telas principais do app passam a ler e gravar dados reais, cobrindo as
   operações básicas (cadastrar, listar, editar e excluir, conforme o escopo do cliente) em pelo menos as
   funcionalidades centrais do app. Tudo o que já era exigido na N1 (fluxo de commit/PR/review/merge,
   diário de bordo individual e README) continua valendo integralmente na N2.
2. Linha do tempo até a N2
   • Conectar o app a um banco de dados real (Firebase Firestore) e substituir os dados mock pelas
   operações reais nas telas que já existiam desde a N1.
   • Ampliar/ajustar as classes de domínio e as Issues do repositório, conforme necessário para a
   integração com banco de dados.
   • Continuar trabalhando com: commit → Pull Request → Code Review de um colega → merge.
   Nunca direto na branch principal.
   • Revisar, aprovar e mergear os PRs dos colegas antes do prazo, nenhum PR relevante pendente ao
   final da fase.
   • Escrever o README v2: atualizar escopo delimitado, RF/RNF, telas principais e instruções para
   rodar, refletindo o estado atual do app com conexão a banco de dados. Obs.: NÃO DELETAR
   INFORMAÇÕES DA N1, apenas façam alterações onde for necessário para que o readme
   corresponda com o estado do app até o momento. Vou deixar um modelo de readme anexado
   na tarefa para facilitar, e para começarem a padronizar.
   • Manter um diário de bordo individual atualizado, com a lista de tarefas de cada um e as evidências
   (prints), separando claramente o que foi feito na N1 do que foi feito na N2. Lembrem-se de que
   pesquisa, alinhamentos e desenvolvimento (commits e Pull Requests aprovados e mergeados) são
   tarefas e devem ser inseridas no diário de quem as fez. Obs.: Tendo em vista que a grande
   maioria não utilizou o modelo de diário da N1, e está tudo bem, não criei uma versão para a
   N2, então podem criar um diário com design/layout que desejarem, e podem entregar nos
   seguintes formatos: PDF, docx e md.
   • Cumprir a distribuição de tarefas combinada no backlog da N2 que o grupo enviou previamente,
   qualquer alteração em relação ao combinado precisa estar relatada e justificada no diário (ver seção
   6).
   • Gerar o APK atualizado a partir do projeto, já com o banco de dados funcional.

   Entrega até 30/10/2026, às 23h59.

6. Lembrando
   PRs não mergeados: um Pull Request aberto que nunca foi revisado, aprovado e mergeado, que
   não entra no app final, terá nota parcial, ressalvas: PRs deixados sem merge com justificativa
   técnica plausível. Cobrar a revisão e garantir o merge antes do prazo faz parte da nota de cada aluno
   (não esqueçam de indicar como tarefa realizada!).
   • Evidenciar apenas a abertura do Pull Request, sem o print da revisão/aprovação e do merge, é
   considerado evidência incompleta para fins de nota do C4, o rastro completo (aberto → revisado
   → aprovado/mergeado) precisa estar nos prints.
   • Cada aluno commita com o seu próprio usuário do GitHub. Trabalho todo commitado por uma
   única conta = sem nota individual para os demais.
   • O README é o contrato: o que não está escrito nele não conta para efeito de nota.
   • Se o projeto não compila a partir do .zip entregue e do apk, C1 e C2 são zerados ou terão nota
   reduzida.
